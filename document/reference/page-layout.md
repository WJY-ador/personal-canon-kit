# 공통 페이지 레이아웃

리스트에서 항목을 고르고 상세에서 읽고 수정하는 공통 화면 규격입니다. 채택한 설계 방향을 설명하며, 아래 화면·필드가 모두 구현됐다는 뜻은 아닙니다. 문서 작성 기준은 [문서 규격](../standard.md)을 따릅니다.

## 리스트와 상세

리스트는 항목을 구별하는 이름·핵심 상태·최근 시점만 보여줍니다. 항목을 선택하면 영역별 상세 페이지에서 글·필드·연결 자료를 읽습니다. 팝업은 짧은 요약과 상세 진입을 제공하고, 전체 정보를 중복 편집하는 별도 화면으로 만들지 않습니다.

같은 필드·레이아웃 정의를 리스트와 상세에서 재사용합니다. 데이터 읽기·편집 권한은 서버 계약을 따릅니다. 이 규격은 범용 페이지 빌더를 새로 도입하는 요구가 아닙니다.

## 필드 표시 계약

| 속성 | 뜻 |
|---|---|
| `type` | 값의 형태. 실행 스키마의 타입을 참조 |
| `source` | 사용자 입력·연결 자료·AI 분석 등 값의 출처 |
| `as_of` | 값이 설명하는 기준 시점. 생성·수정 시각과 구분 |
| `editable` | 해당 사용자가 수정할 수 있는지. 화면 표시만으로 권한을 부여하지 않음 |
| `empty` | 미입력·미확인·미수집·불러오기 실패를 구분하는 빈 상태 |

실행 속성명·저장 형식은 구현 계약에서 정합니다. 설명 표와 실행 스키마가 각각 다른 규칙을 갖지 않게 합니다. 없는 값을 0이나 부정으로 대신하지 않고, 모든 빈 필드를 첫 화면에 펼치지 않습니다.

## Contact 적용

리스트에서는 별칭·사용자가 정한 관계·최근 대화·자료 상태를 요약합니다. 상세 페이지는 다음 영역으로 구성합니다. 지원 데이터 범위는 별도 계약과 정책을 따르며, 이 레이아웃이 수집·보관 허용 범위를 넓히지는 않습니다.

| 영역 | 내용 |
|---|---|
| 기본 정보 | 허용된 별칭·사용자가 정한 관계 등 직접 관리하는 값 |
| 내 메모 | 사용자가 남긴 글과 수정 이력 |
| 최근 활동 | 기간·자료 범위가 확인되는 연결 활동 |
| 분석 | 대상·기간·사용 자료·생성 시각·모델을 갖는 분석 스냅샷 |
| 근거 | 분석·메모에 연결된 자료, 당시 판, 접근 가능한 원문 |

사용자가 관리하는 값과 분석 스냅샷을 분리합니다. 분석은 관찰과 추론을 구분하며 사용자 입력값을 자동으로 덮어쓰지 않습니다. 말수가 많다는 이유로 친밀도를 단정하거나, 별칭이 같다는 이유로 동일인으로 병합하지 않습니다. 성향 정보는 본인이 밝힌 값과 추론을 구분하고 모르면 미확인으로 둡니다. 분석 항목과 물리 저장 구조는 별도 검증 대상입니다.

## 글·출처·동작

- 기존 내용을 바꾸는 진입 버튼은 **[수정]**, 편집 완료는 **[저장]**입니다. **[AI]**는 추가 대화를 여는 동작이며 저장·확정 승인이 아닙니다.
- 참고 출처는 제목·유형·날짜를 한 줄로 보여줍니다. 게시일과 수집일을 구분하며 알 수 없는 게시일을 수집일로 대신하지 않습니다. 원문·이력 등 상세는 펼쳐 봅니다.
- 일지의 기존 본문은 기본적으로 보존하고 구체화된 내용을 날짜별로 덧붙입니다. 추가 문단과 근거를 함께 읽게 하며 반복 설명·빈 양식·내부 ID를 앞에 내세우지 않습니다.
- 명시적인 반영 행동은 같은 내용의 최종 확인을 반복하지 않습니다. 저장 실패·충돌·반영 대기는 성공과 구분하고 사용자가 작성한 입력을 보존합니다.
- 화면 상단 AI 정보는 실제 연결 상태와 공식적으로 조회 가능한 사용량·갱신 시각만 표시합니다. 조회 불가한 잔여량을 추정해 채우지 않습니다.

## 검증 기준

처음 읽는 사람이 주체·핵심 내용·시점을 이해할 수 있어야 합니다. 필요한 경우 보고서 문장에서 연결 자료와 당시 판까지 따라갈 수 있어야 합니다. 빈 상태·권한·저장 충돌·오프라인·키보드 접근을 확인하고 macOS·Windows의 실제 지원 조건을 각각 검증합니다. 이 문서의 존재는 그 시험을 통과했다는 증거가 아닙니다.
