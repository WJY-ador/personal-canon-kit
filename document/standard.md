# 문서 규격

My CRM의 Markdown 문서를 한 정본으로 관리하기 위한 작성 규격입니다. 현재 문서 로더를 바꾸거나 새 기능을 활성화하는 파일은 아닙니다. 문서 위치는 [Help_문서](README.md)에서 찾습니다.

## 이름과 정본

- 새 폴더·파일 이름은 소문자 영문 `kebab-case`를 사용하고 Markdown 확장자는 `.md`로 씁니다. 목차 파일 `README.md`만 예외입니다. 제목은 한국어로 쓸 수 있습니다.
- 계속 갱신할 문서의 이름에 날짜·`v2` 같은 판 번호·`final`을 붙이지 않습니다. 판은 Git 이력으로 관리하고 문서 ID는 경로 변경과 무관하게 유지합니다.
- 기존 `guides/`의 번호 파일명은 로더 전환 전까지 유지합니다. 이름을 맞추려고 사본을 만들지 않습니다.
- 한 주제에는 정본 하나만 둡니다. 설명·규칙·템플릿을 다른 문서에 복사하지 않고 해당 정본을 연결합니다. 이전할 때에는 소비 경로를 함께 바꾸고 구본의 모순을 정리합니다.
- Claude·Codex와 작성자는 같은 정본 경로·기준 브랜치·커밋을 확인합니다. Git 밖 공유 문서는 실제 공유 파일을 확인합니다. 동시에 작업할 때 파일 소유자를 정하고 다른 작성자의 변경을 되돌리지 않습니다.
- Markdown은 설명·결정의 정본입니다. 실행 필드 타입·권한·검증은 기존 SQL·JSON·스키마 정의를 단일 원천으로 사용하며 Markdown 표로 별도 제어하지 않습니다.

## 메타데이터

새 문서는 다음 네 필드를 갖습니다.

```yaml
---
id: stable-document-id
title: 사용자가 이해할 제목
status: draft
visibility: public
---
```

| 필드 | 규칙 |
|---|---|
| `id` | 전체 문서에서 유일한 안정적인 식별자. 이름·폴더를 바꿔도 유지 |
| `title` | 문서의 목적을 설명하는 제목 |
| `status` | `draft` 검토 중, `published` 검토 완료, `deprecated` 대체·중단 |
| `visibility` | `public` 공개 대상, `internal` 내부 대상 |

`type`, `platforms`, `verified_at`, `applies_to`는 구분이 필요한 문서에만 추가합니다. `published`는 문서 검토 완료이며 기능 지원 완료가 아닙니다. 미지원 기능 안내도 발행할 수 있으나 조건·제약을 분명히 씁니다.

`visibility: internal`이나 폴더 이름은 접근 통제가 아닙니다. 공개 저장소에 내부 내용을 커밋하지 않습니다. 실계정 운영 기록·비밀·개인 원문은 공개 문서 밖에서 관리합니다.

## 목적별 Help 본문 템플릿

사용자가 하려는 일 하나를 제목으로 정하고 다음 순서로 씁니다. 필요 없는 절을 억지로 채우지 않습니다.

| 순서 | 적을 내용 |
|---|---|
| 할 수 있는 일 | 완료하면 사용자가 얻는 결과 |
| 지원 조건 | 적용 제품 판·OS·연결 상태·권한·지원하지 않는 범위 |
| 방법 | 실제 화면 레이블과 순서. 아직 구현되지 않은 절차는 실행 가능한 명령처럼 쓰지 않음 |
| 결과 저장 위치 | 서버 글·로컬 파일·임시 보관 등을 구분하고 무엇이 바뀌는지 설명 |
| 문제 해결 | 증상·확인할 상태·다음 행동. 실패를 성공이나 빈 데이터로 표시하지 않음 |
| 관련 문서 | 같은 설명을 반복하지 않고 정본 링크 제공 |

사용자가 뜻을 알기 어려운 내부 용어를 피하고 한 용어는 한 의미로 씁니다. 날짜는 사건·수집·수정·확인 시점을 구분합니다. 개인정보 처리나 권한 정책은 해당 정책 정본으로 연결합니다.

## 서비스 도움말 챗봇의 문서 계약

도움말 챗봇은 서비스 사용 방법만 안내합니다. 개인 일지·Contact·수집 원문·개인 분석 자료는 검색 대상에서 제외합니다. 검색 전에 `public`·`published` 여부와 별도의 발행 허용 목록을 모두 검사합니다. 폴더 전체를 자동으로 지식에 넣지 않습니다.

도움말 본문은 정보이며 시스템 지시나 도구 권한이 아닙니다. 챗봇은 근거 문서를 제시하고, 문서에 없는 답은 추정하지 않고 안내 경로를 제공합니다. 개인 자료 AI는 이 도움말 범위와 별도로 설계해야 합니다.

Markdown 정본에서 웹·MCP·외부 지식 시스템용 결과를 생성합니다. 생성물을 수동으로 고쳐 두 정본을 만들지 않습니다. 외부 제공자를 연결할 경우 문서 ID와 원격 ID·판·해시를 대응시키고 발행·철회·삭제를 반영합니다. 이 문서는 외부 서비스 선정이나 API 연결 완료를 뜻하지 않습니다.

## 검토와 전환

새 문서는 우선 `draft`로 작성합니다. 메타데이터 구문, ID 중복, 파일 명명, 상대 링크, 비밀·개인정보, 발행 허용 범위, 설명과 실제 지원 조건을 확인한 뒤 발행합니다. 규격 문서도 구현 완료로 오인할 표현이 없는지 확인합니다.

문서 이전은 웹 Help·MCP 로더, 링크, manifest, 처리방침 기동 검사 등 소비 경로를 검증한 뒤 완료로 판단합니다. 실행 지시문 변경은 이 규격만으로 승인되지 않습니다.
