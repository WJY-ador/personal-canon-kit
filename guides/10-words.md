# 10. 말 뜻 — 화면과 대화에 나오는 단어

한 단어에 뜻 하나. 웹 화면과 이 가이드는 같은 말을 씁니다. 대화에서는 예전 말로 말해도 됩니다 — AI 가 부르는 도구 이름이 그대로라서입니다.

## 바뀐 말

| 지금 말 | 예전 말 | 도구 이름(그대로) |
|---|---|---|
| **내 글** | 기록 · 내가 쓴 글 | `record_*` |
| **검토할 판단** | 후보 | `candidates_propose` · `candidate_*` |
| **확정한 판단** | 내 판단 | `candidate_decide` 로 남김 |
| **읽고 든 생각** | 출처 요약/반응 | `source_reflection_*` |
| **확인 전** | 검토 대기 | — |
| **확인했어요** | 검토 완료 | `source_reflection_review` |
| **내 글 AI 요약** | AI 요약 | — |
| **저장 승인 대기** | 승인 대기 | `inbox_*` |
| **자료 종류** | 오브젝트 | `definition_*` · `definitions_get` |
| **공통 구조 적용 검토** | 표준 편입 미리보기 | — (웹에서만) |
| **커스텀** | 선택 템플릿 · 직접 추가 | — |

질문은 그대로 질문입니다.

## 흐름을 이루는 네 단어

| 말 | 뜻 | 누가 만드나 |
|---|---|---|
| **내 글** | 내가 겪은 일을 내 말로 적은 원문 1편, 또는 내가 확인한 대화 정리 1편. 저장 뒤 바뀌지 않습니다 | 나(대화에서, 또는 웹 「대화」의 [확정]) |
| **검토할 판단** | 내 글에서 뽑힌 "판단이 될 만한 문장" + 원문의 근거 구절. **아직 확정한 판단이 아닙니다** | AI(대화에서) 또는 내가 글에 쓴 메모 |
| **확정한 판단** | 검토할 판단을 원문과 대조해 내가 **남기기로 한** 문장. 남긴 뒤엔 문장을 덮어쓰지 않습니다 | 나(웹 또는 대화에서 결정) |
| **질문** | 계속 돌아와 묻는 것. 검토할 판단과 확정한 판단이 질문 밑에 쌓입니다 | 나(대화에서). 없어도 시작할 수 있음 |

판단의 상태는 셋 — **아직 안 정함 · 확정한 판단 · 남기지 않음**. 아직 안 정한 것만 「검토할 판단」이라 부릅니다. 누가 뽑았나 표시는 둘 — **AI가 쓴 문장 · 내가 쓴 메모**. 고치면 「내가 고침」이 붙습니다.

## 글 셋의 구분

| 말 | 무엇 | 판단 근거로 인용 |
|---|---|---|
| **내 글** | 내가 직접 쓴 원문 · 내가 확인한 대화 정리. 화면에서는 둘을 나누지 않습니다 | 됩니다(내가 쓴 원문 그대로일 때, 또는 대화 정리를 내가 [확정]했을 때) |
| **읽고 든 생각** | 출처를 접한 뒤 내가 한 생각. 안에서 **내 요약 · 내 반응**으로 나뉩니다 | 안 됩니다 |
| **내 글 AI 요약** | PC 의 구독 CLI 가 내 글을 요약한 것. 이 이름은 저장 승인 대기(「오늘」의 「대기」 글)에서만 보입니다 | 안 됩니다 |

## 나와 사람, 출처

| 말 | 뜻 |
|---|---|
| **표시 이름** | 계정과 「나」 홈에 쓰는 내 이름. 꼭 정해야 하고, 실명이 아니어도 됩니다. 다른 사람에게 보이지 않고 운영자 화면에도 나오지 않습니다 |
| **연결** | 상세 아래 영역. 고른 데이터와 실제로 저장된 관계로 이어진 데이터만 보여 줍니다. 같은 출처·비슷한 문장·같은 날짜만으로는 잇지 않습니다 |
| **사람** | 내가 관계를 구분하려고 붙인 별칭 이름표 하나. 연락처·소속·SNS 주소·그 사람의 말·평가는 넣지 않습니다. 별칭도 그 사람을 알아볼 수 있으면 개인정보입니다. 연결 장치가 처음 보는 사람은 「사람-0001」 꼴 별칭으로 생기고, 별칭은 내가 바꿀 수 있습니다. 활동·내 글·항목에 연결된 사람은 지울 수 없습니다 |
| **출처** | 내 글이 어디서 왔는지(파일·웹 주소·대화). 연결한 AI 가 글을 남길 때 함께 붙이고, 이전 글은 「출처 미확인」으로 보입니다. 연결 장치가 보낸 활동은 서버가 정한 일반 출처(「SNS 활동」·「웹 활동」·「메일 활동」·「카카오톡 활동」)에 붙습니다 |
| **읽고 든 생각** | 출처를 접한 뒤 내가 한 생각. 안에서 **내 요약 · 내 반응**으로 나뉩니다. 다른 사람의 말·경험·생각을 옮기는 곳이 아닙니다 |
| **확인 전 · 확인했어요** | 읽고 든 생각의 상태(연결 장치가 보낸 글이 머무는 곳은 「저장 승인 대기」로 따로 부릅니다). 처음엔 확인 전이고, 내가 말하거나 [확인했어요]를 눌러야 바뀝니다. [확인 전으로]로 되돌릴 수 있고, 고치면 다시 확인 전. 확인했어요는 **판단 확정이 아니고**, 판단·기준의 근거로 인용할 수 없습니다 |

내 글에는 내가 직접 쓴 글과 내가 확인한 대화 정리만 넣습니다. 읽고 든 생각에도 내 생각만 적습니다.

## 화면 단어

| 말 | 뜻 |
|---|---|
| **「나」** | 첫 화면. 위에 표시 이름, 그 아래 하위 탭 일곱과 축 띠가 있습니다 |
| **하위 탭** | 「나」 안의 일곱 — 요약 · 기준 · 결정 · 축 · 커스텀 · 사람 · 출처. 순서는 페이지 레이아웃에서 바꿉니다. 이름 옆 숫자는 그 종류 전체 건수입니다 |
| **기본 🔒 · 커스텀** | 화면의 자료 구분 둘. **기본 🔒** = 모든 사용자에게 같은 종류(기준 · 결정 · 축 · 사람 · 출처와 질문 · 내 글 · 판단 등). **커스텀** = 내가 들인 종류. 코어·표준 구분(아래 「자료 종류와 구분」)은 내 구조 설정에서만 보입니다 |
| **축 띠** | 「나」 하위 탭 아래 색 띠와 칩. 축마다 직접 연결된 항목·글·읽기 자료 수와 그 비율입니다. 한 글이 두 축에 붙으면 두 축에서 한 번씩 셉니다. 축 색은 코드 순이고 아홉 번째부터 회색 — 건수와 상관없이 그대로입니다 |
| **요약** | 「나」의 첫 하위 탭. 13주 글·활동 · 종류별 건수 · 기다리는 결정 · 최근 변경 5. 버튼이 없습니다 |
| **13주 글·활동** | 오늘이 든 주까지 13주(월요일 시작)의 날짜별 칸. 글은 원래 쓴 날, 활동은 행동한 날로 셉니다 — 날짜를 모르는 글·활동은 빠집니다. 진할수록 그날 많습니다 |
| **기다리는 결정** | 아직 내가 정하지 않은 것의 수 — 검토할 판단 · 확정 전 기준 · 저장 승인 대기 |
| **렌즈** | 하위 탭을 보는 방식. 기준·결정 = **근거 역추적**(무엇을 근거로 섰나), 축 = **축 묶음**(그 축에 무엇이 붙었나), 사람 = **사람 관계**(그 사람과 이어진 활동·글·항목). 저장된 관계만 그립니다 |
| **「오늘」** | 들어온 것 전부 — 저장 승인 대기 글과, 승인해 저장된 내 글 · 연결 장치가 보낸 활동. 들어온 날(한국 시간)로 묶습니다. 삭제는 없습니다 |
| **대기 · 보관됨** | 「오늘」의 줄 상태. **대기** = 아직 저장 전(승인해야 저장). **보관됨** = 저장된 것 |
| **Setup** | 세 번째 탭. 페이지 레이아웃 · 내 구조 설정 · 자료 종류 · 연결 장치 · 지도 · 문의 및 개인정보 |
| **페이지 레이아웃** | Setup 첫 페이지. 「나」 하위 탭 순서와 요약 블록 순서를 끌어 놓아 바꿉니다. 놓으면 바로 저장되고, [기본으로 되돌리기]로 처음 순서로 돌아갑니다. 내 계정에만 적용됩니다 |

## 연결 장치와 활동

내 PC 에 로컬 에이전트를 두고 계정에 연결하면, PC 가 정해진 활동과 내 글을 보냅니다. 다른 사람의 원문은 PC 에만 남습니다. 새 탐색에서만 보입니다.

| 말 | 뜻 |
|---|---|
| **연결 장치** | 이 계정에 연결한 PC 하나. Setup › 연결 장치(계정 메뉴 「연결 장치」도 같은 곳)에서 연결·토큰 재발급·연결 해제·허용 규칙 바꾸기를 합니다. 최대 5대. 토큰은 연결·재발급 때 한 번만 보이고 90일 뒤 만료됩니다. 연결을 해제한 장치는 되살리지 않습니다(새로 연결) |
| **로컬 에이전트** | 내 PC 에서 도는 프로그램. 수집기 산출물을 활동으로 바꿔 보내고, 원문을 PC 에 보관하고, 원문 열기를 맡습니다 |
| **허용 규칙** | 연결 장치마다 서버가 받을 것 — 행동(좋아요 등)·받는 것(좋아요 활동은 바로 저장, 내 글과 내 글 AI 요약은 저장 승인 대기로)·축. 바꾸면 PC 의 로컬 에이전트가 다음 업로드 때 새 규칙을 자동으로 다시 받아 이어 갑니다(토큰을 다시 넣지 않습니다). 새 규칙이 막는 것은 보내지 않습니다 |
| **활동** | 내가 한 행동 한 건 — 좋아요·리포스트·댓글·답장·읽음·보관·보냄. 행동·날짜·출처 종류·사람 별칭·축만 있고 원문은 없습니다. 허용 규칙대로 바로 저장되고, 활동 자체엔 내가 승인할 글이 없습니다 |
| **활동 현황** | Setup › 자료 종류 › 활동 화면 위의 접힌 집계. 기본 최근 30일(7일·90일·전체도), 한국 시간 오늘 포함. 계산 규칙은 숫자 옆 「?」에 있고, 성향 평가가 아닙니다 |
| **행동 날짜 · 날짜 미확인** | 행동한 날이 확인된 활동만 날짜가 있습니다. 모르면 「날짜 미확인」이고, 기간 집계(최근 7일·30일·90일)에서 빠지고 따로 셉니다 |
| **처음 수집한 날** | PC 수집기가 그 활동을 처음 본 날. 행동한 날이 아닙니다. 날짜 미확인 활동의 참고로만 보이고 기간 집계에 쓰지 않습니다 |
| **축 미분류** | 축에 연결되지 않은 활동 수. 축이 여러 개인 활동은 축마다 한 번씩 세서, 축별 합계가 전체와 다를 수 있습니다 |
| **자주 반응한 사람** | 좋아요·리포스트·댓글·답장 활동에서 작성자·상대로 연결된 별칭별 활동 수. 사람마다 한 번씩이라 합계는 전체 활동량이 아닙니다. 친밀도·영향력 점수가 아닙니다 |
| **저장 승인 대기** | 연결 장치가 보낸 내 글과 내 글 AI 요약이 저장 전에 머무는 곳(종류 표시 「내 글」 · 「내 글 AI 요약」). 「오늘」에 「대기」로 보이고, 탭 이름 옆 숫자가 승인할 수 있는 글 수입니다(계정 메뉴 「저장 승인 대기 (N)」도 「오늘」을 엽니다. 0 이면 숫자가 없습니다). 상태는 넷 — **대기 · 승인함 · 제외함 · 만료**. 승인해야 내 글이 되고, 대기 본문은 30일 보관합니다. 승인·제외·만료 때 대기 본문을 지웁니다. 승인·제외는 웹에서 내가 합니다 — AI 가 대신하지 않습니다 |
| **내 글 AI 요약** | PC 의 구독 CLI 가 내 글을 요약한 것. 승인하면 「내 글」로 들어가지만 AI 생성으로 저장돼, 직접 쓴 원문이나 인용 가능한 글로 바뀌지 않습니다. 도구·모델 정보는 연결 장치가 신고한 값입니다 |
| **무인 실행** | 사람이 지켜보지 않을 때 PC 가 예약으로 돈 것(PC 가 켜져 있을 때만). 무인 실행으로 만드는 내 글 AI 요약은 이용 조건을 확인하기 전까지 꺼 둡니다 |
| **원문 열기** | 활동 상세의 [원문 열기 · 이 PC]. 로컬 에이전트의 원문 보기(기본 포트 8790)가 켜진, 원문을 보관한 그 PC 에서만 열립니다. 포트를 바꿨으면 버튼 아래 「로컬 연결 포트」에서 같게 맞춥니다(그 브라우저에만 저장). 서버는 원문을 가져오거나 미리 보여 주지 않습니다. 휴대폰·태블릿에서는 버튼 대신 「원문을 보관한 PC에서 열 수 있습니다」만 보입니다 |
| **현재 판 · 옛 판** | PC 에서 같은 원본이 바뀌면 새 판으로 들어옵니다. 집계는 현재 판만 세고, 옛 판을 가리키던 연결은 옛 판을 그대로 가리킵니다 |

## 대화로 쌓기

웹 「대화」로 말하거나 원문을 던지면, 연결 장치(내 PC)가 내 구조에 맞춰 정리하고 나는 한 번 확인합니다. 운영자가 켠 계정에만 보입니다. 쓰는 법은 [09. 시작](09-hosted-start.md) 2-1절.

| 말 | 뜻 |
|---|---|
| **대화** | 탭 줄 오른쪽 서랍. 말하기·원문 던지기 → PC 정리 → 확인 1번. 버튼은 [보내기] · [확정] · [닫기] |
| **쌓기 단계** | 입력 1건을 내 구조에 맞춰 쌓는 PC 의 뒷단 처리 — 같은 대상이 있으면 고치고 없으면 만들기 · 칸 채우기 · 구조에 정의된 관계로만 연결 · stage 갱신 · 정하지 못한 것 묶기 · 정리 글 쓰기. Phase(1·2)와 다른 말입니다 |
| **대화 정리** | 대화 한 세션의 결과 글과 변경 목록. AI 가 쓰고 내가 고쳐 확정합니다. 확정하면 「내 글」이 되고 직접 쓴 원문과 화면에서 나누지 않습니다. 확정 전에는 내 글이 아닙니다 |
| **확인** | 대화 정리를 [확정]으로 한 번 승인하는 것. 항목마다 승인하지 않고 틀린 변경만 끕니다. 확인한 대화 정리는 판단의 근거로 인용할 수 있습니다. AI 가 대신 확인하지 않습니다 |
| **임시 보관** | 확정 전 정리 결과를 서버에 잠시 두는 것. 첫 입력 뒤 24시간에 지우고(더 말해도 늘지 않음), 운영 백업에 넣지 않습니다. 판단 근거·인용·집계에 쓰지 않습니다 |
| **원문으로 저장** | 대화 첫 입력 때만 고르는 선택. 고르면 붙여 넣은 원문도 「내 글」로 함께 남습니다 — 정리 글과 원문 2편이 같이 저장되거나 같이 저장되지 않습니다 |
| **재정리** | 정리 글을 고친 뒤 정리 글 밖을 누르면 고친 글로 다시 정리하는 것. 고치는 순간 [확정]이 잠기고, 새 결과가 뜬 뒤 다시 켜집니다. 따로 누르는 버튼은 없습니다 |
| **추정** | 정리 글 문장 옆 표시. AI 가 문맥으로 대상을 고른 변경입니다. 확인하면 그대로 저장되니 틀리면 고치거나 끕니다 |
| **stage** | 항목의 진행 칸 — **초안(draft) → 정리됨(organized) → 확정(confirmed)**. 필수 칸이 다 차면 정리됨, 기준처럼 판단인 항목을 내가 확정하면 확정. 서버가 계산하고, 내가 직접 바꾸는 화면은 없습니다. 처리 과정이 아니라 항목의 칸입니다 |

## 자료 종류와 구분

네 단어 위에, 사람마다 다른 자료를 쌓습니다. 자료 종류마다 **구분**이 하나 붙습니다. 화면(「나」·Setup › 자료 종류)에선 코어·표준을 묶어 「기본 🔒」, 나머지를 「커스텀」으로 보이고, 아래 세 구분은 내 구조 설정에서 봅니다.

| 구분 | 뜻 |
|---|---|
| **코어** | 모든 사용자에게 같은 기본 자료 — 질문·내 글·판단(검토할 판단·확정한 판단)·문의·출처, 그리고 나·사람·읽고 든 생각·활동 |
| **표준** | 서비스가 정한 공통 구조 셋 — **축 · 결정 · 기준** |
| **커스텀** | 표준 밖의 자료 종류. 내가 대화에서 정의한 것과, 골라서 들인 정의 묶음(예: 원작자 템플릿) |

표준 셋:

| 말 | 뜻 | 예 |
|---|---|---|
| **축** | 관심 축. 내 글·기준을 묶는 태그. 축 항목을 먼저 만들고 글을 붙입니다. 「나」의 축 띠로 축마다 붙은 수를 봅니다 | 「범위 관리」 |
| **결정** | 실제로 내린 결정 한 건의 색인(언제·어디서·무엇을) | 「A사 견적 승인 — 표준으로 결정」 |
| **기준** | 여러 확정한 판단을 종합해 내가 확정한 **한 문장**. 결정 상태(아직 안 정함·확정·남기지 않음)와 승격 조건이 있습니다 | 「정본이 어디인지 먼저 고정한다」 |

원작자 템플릿(커스텀)에는 표준 셋 말고 모음 셋이 더 있습니다. 축은 표준으로 옮겼습니다.
- **숙제** — 기준·결정·판단에 달린 아직 못 푼 물음. 답하면 내 글이 연결됩니다.
- **발행** — 밖으로 나간 글(채널·날짜·핵심 한 줄·재료가 된 내 글).
- **접근 방식** — 결정이 바뀌진 않았지만 남겨 둘 만한 접근(프로젝트·요지·관련 결정).

**공통 구조 적용 검토** — 표준을 내 구조에 들일지 고르는 화면. Setup › 내 구조 설정 › 고급에 있습니다. 새로 가입한 계정은 표준 셋이 처음부터 들어 있어 고를 것이 없습니다. 이미 쓰던 계정만 내 구조와 표준을 비교해 **편입·보류·거절**을 직접 고릅니다. 고르지 않아도 다 쓸 수 있습니다.

**공통 구조 적용(=편입)** — 표준을 내 구조에 들이는 것. 화면 본문엔 「편입」으로 나옵니다.

**표준 정의 보호** — 처음부터 들어 있는 표준과 편입한 표준이 받습니다. label(표시명)은 바꿀 수 있지만 표준 필드는 빼거나 모양을 바꿀 수 없고, 표준 자료 종류는 보관할 수 없습니다. 내가 더한 필드는 자유롭게 고칩니다.

**보관** — 자료 종류나 항목을 목록에서 빼 두는 것. 지우지 않습니다. 자료 종류를 보관하면 「내 구조 설정」 목록에서 빠지고, 그 항목은 그대로 남습니다. 자료 종류 보관·되살리기는 대화에서 말해서 합니다. 표준 자료 종류와 아직 적용하지 않은 제안은 보관할 수 없습니다.

내 구조는 내가 정합니다. 표준에 없는 자료도 커스텀으로 쌓습니다. 대화에서 "이런 자료를 쌓고 싶어"라고 말하면 AI 가 **정의 제안**을 내고, 내가 적용합니다.

## 새 탐색

**새 탐색** — 탭 셋(나 · 오늘 · Setup)으로 바뀐 화면. 새로 가입한 계정은 처음부터 새 탐색입니다. 이미 쓰던 계정은 계정 메뉴 「새 탐색으로 바꾸기」에서 한 번 수락합니다. 표준 편입과 따로입니다. 데이터는 바뀌지 않고, 되돌리는 화면은 없습니다.

**자료 종류** — Setup 의 한 페이지. 모든 자료 종류를 「기본 🔒」 · 「내 탭」 · 「커스텀」 묶음으로 보여 줍니다. 「내 탭」은 설정 때 이름 지은 글·질문 탭입니다(구분이 아니라 묶음). 질문·내 글·검토할 판단·사람·출처·활동 목록과 종류별 항목 화면이 여기 있습니다.

**내 구조 설정** — Setup 의 한 페이지(계정 메뉴에서도 엽니다). 자료 종류·필드·관계를 「그래프」(기본)와 「목록」으로 보고, 「구조 이름 공유」(켜짐/꺼짐)와 「고급」 › 「공통 구조 적용 검토」가 있습니다.

## 제안과 적용

AI 는 기준·결정·정의를 **제안**만 합니다(서랍에 「제안이 있어요」). 적용·확정·남기기는 **내가 말하거나 버튼을 눌러야** 됩니다. 제안이 마음에 안 들면 [제외] — 흔적 없이 사라집니다. 적용 전 제안은 **초안(draft)**입니다. 새 자료 종류 초안은 화면 목록에 나오지 않습니다 — 제안한 대화에서 "아까 제안한 정의 다시 보여 줘"라고 하면 AI 가 다시 읽어 줍니다.

## 승격

표준 기준은 **확정한 판단 2개 이상**이 근거로 붙으면 "승격 조건 충족"으로 표시됩니다. 커스텀 묶음의 기준은 조건이 다를 수 있습니다(원작자 템플릿은 서로 다른 결정 2건도 요구). 충족 여부는 **사실 표시**일 뿐, 남길지는 내가 정합니다.

## 되돌리기

판단 결정·기준 결정·항목 변경은 전부 **이력**에 남습니다. 되돌리기도 새 변경으로 남습니다. 이 이력은 지워지지 않습니다 — 계정 삭제 때만 지워집니다. 삭제 뒤 남는 것은 [11. 처리방침](11-privacy.md) 3절.

## 자주 묻는 것

**검토할 판단이 왜 바로 확정한 판단이 아니죠?** — AI 가 뽑은 문장은 내 말을 요약한 추정입니다. 원문과 대조해 내가 남겨야 확정한 판단입니다.

**원문을 고칠 수 있나요?** — 아니요. 내 글 원문은 저장 뒤 바뀌지 않습니다. 검토할 판단 문장은 「고쳐서 남기기」로 고칠 수 있고, 고친 흔적이 남습니다. 확정한 판단 문장은 덮어쓰지 않습니다.

**AI 가 내 대신 확정할 수 있나요?** — 그렇게 설계돼 있지 않습니다. 대화 지시문이 "사용자가 말하기 전엔 확정 도구를 부르지 않는다"이고, 제안은 적용 전까지 초안(draft)으로만 저장됩니다. 다만 지시문은 규칙이지 기술적 봉쇄는 아니라서, 화면에서 확정 이력을 확인하는 습관이 안전합니다. 웹 「대화」의 정리 결과는 내가 [확정]을 누르기 전에는 저장되지 않습니다.

**질문이 없으면요?** — 검토할 판단은 질문 없이도 「나」 › 요약 「기다리는 결정」 › 검토할 판단에 뜹니다. 질문은 나중에 만들어도 됩니다.

**내 데이터는 어디에?** — 서버 DB(Supabase, 싱가포르). 화면과 도구는 내 계정 행만 보여 줍니다. 운영자는 방침상 본문을 열람하지 않고 운영 상태(사용자 수·오류)와 구조의 개수·종류·표준 편입 상태, 출처 개수만 봅니다(이름은 「구조 이름 공유」 동의자만). 표시 이름·사람·읽고 든 생각·활동과, 항목이 사람·출처·활동을 가리키는 관계는 운영자 화면에 값도 개수도 나오지 않습니다. 기술적으로는 DB 관리자라 접근이 가능하다는 점은 숨기지 않습니다.

**다른 사람의 글 원문도 서버에 가나요?** — 아니요. 연결 장치는 다른 사람의 글·메시지·메일 원문과 그 제목·URL 을 PC 에 두고, 서버엔 내 행동·날짜·별칭·관계만 보냅니다. 원문은 그 PC 에서 [원문 열기]로 봅니다. 자세한 것은 [11. 처리방침](11-privacy.md) 2절.

**다른 사람과 같이 쓸 수 있나요?** — 아니요. 한 사람의 노트입니다.
