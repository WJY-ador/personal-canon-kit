# 09. 호스팅 판 — 연결하고 첫 하루

호스팅 판은 설치가 없습니다. 내 ChatGPT·Claude 구독으로 서버에 연결해 내 글·검토할 판단을 남기고, 웹에서 보고 결정합니다. 모델 호출은 서버에 없고 내 구독만 씁니다.

## 1. 연결

| 어디서 | 어떻게 |
|---|---|
| Claude (claude.ai) | 설정 › 커넥터 › 커스텀 커넥터 추가 → 주소 `https://personal-mycrm.onrender.com/mcp` → 로그인 창에서 Google 또는 이메일 코드 |
| Claude Code | `claude mcp add --transport http my-crm https://personal-mycrm.onrender.com/mcp` 뒤 `/mcp` 에서 로그인 |
| ChatGPT | Developer Mode 의 커넥터 추가(같은 주소). 2026-10 기준 Business 이상에서 쓰기 도구를 허용합니다 — Plus/Pro 는 아직 확인하지 못했습니다 |
| 웹 | `https://personal-mycrm.onrender.com/` → [로그인]. 같은 이메일이면 대화와 웹이 한 계정입니다 |

처음 로그인하면 계정이 만들어집니다. 무료 서버라 15분 쉬면 잠들어요 — 첫 응답이 30~60초 걸릴 수 있습니다.

**표시 이름을 먼저 정합니다.** 웹에 처음 들어가면 이름 입력 화면이 뜹니다. 실명이 아니어도 되고, 다른 사람에게 보이지 않고 운영자 화면에도 나오지 않습니다. 표시 이름을 정하기 전에는 대화에서 글·판단 남기기 같은 쓰기를 할 수 없습니다(읽기·도움말·문의는 됩니다). 이미 쓰던 계정도 다음 웹 로그인 때 한 번 정합니다.

## 2. 첫 하루 — 네 마디면 됩니다

대화에서는 예전 말(「기록」·「후보」)로 말해도 됩니다 — 도구 이름이 그대로라서입니다. 대응은 [10. 말 뜻](10-words.md) 「바뀐 말」.

1. **글 남기기** — 대화에서 "오늘 있었던 일 기록 남길게. …" 라고 말합니다. AI 가 내 말을 **그대로** 저장합니다(다듬지 않음). 웹에선 「내 글」로 보입니다.
2. **검토할 판단 뽑기** — "후보 뽑아 줘". AI 가 글에서 판단이 될 만한 문장을 최대 3개 뽑고, 각 문장의 **근거 구절**을 원문에서 글자 그대로 가져옵니다. 원문에 없는 구절은 서버가 거절합니다.
3. **대조** — 웹 「나」 › 요약의 「기다리는 결정」에서 「검토할 판단」을 누릅니다(Setup › 자료 종류 › 검토할 판단도 같은 곳). 판단을 열면 문장과 근거 구절이 뜹니다. [남기기] · [고쳐서 남기기] · [반영 안 함].
4. **질문** — 같은 종류의 판단이 모일 것 같으면 "이 질문 남길게: …". 그 뒤 검토할 판단은 질문 밑에 쌓입니다. 질문은 나중에 정해도 됩니다.

## 2-1. 웹 「대화」로 쌓기 — 탭 줄에 「대화」가 보일 때

탭 줄 오른쪽에 「대화」가 보이면, 웹에서 말하거나 원문을 던지고 **한 번 확인**해 쌓을 수 있습니다. PC 를 연결한 사용자에게 보입니다. 정리는 연결 장치(내 PC 의 로컬 에이전트)가 내 구독 CLI 로 합니다 — PC 가 켜져 있어야 하고, 서버는 모델을 부르지 않습니다.

연결한 장치가 없으면 「대화」 자리에 「이 기능은 본인 PC에서 본인 Claude 구독으로 실행하며, PC 연결과 에이전트 실행이 필요합니다.」 한 줄만 보입니다. Setup › 연결 장치에서 PC 를 연결하면 「대화」가 나타나고, 정리는 그 PC 에서 로컬 에이전트가 돌아야 됩니다. 확정 전 대화가 남아 있으면 장치가 없어도 서랍이 열리고, 변경 끄기와 [확정]만 됩니다(새로 보내기·다시 정리는 안 됩니다). 다른 사람의 PC·구독으로 대신 정리하지 않습니다.

**PC 에서 정리 켜기** — 연결 장치를 붙인 PC 의 터미널에서, 키트 루트(`agent/` 폴더가 있는 곳)로 가서 실행해 둡니다. 켜 둔 동안 정리가 됩니다.

```bash
MYCRM_JOBS_ALLOW_REAL_CLI=1 python3 -m agent serve --jobs
```

`MYCRM_JOBS_ALLOW_REAL_CLI=1` 은 이 PC 에서 내 구독 CLI(`claude`)로 정리를 돌리겠다는 내 동의입니다 — 빼면 시작하지 않습니다. 끄려면 그 창에서 Ctrl+C. `claude` 를 찾지 못해 멈추면(출력에 `cli-not-found`) 로컬 에이전트 설정의 `summary.cli_path` 에 `claude` 의 절대 경로를 적습니다 — [agent/README.md](../agent/README.md) 11절.

**자기 구독** — PC 에서 내 로그인으로 쓰는 Claude 계정입니다. 개인 Pro·Max 또는 조직이 준 Team·Enterprise 좌석이면 됩니다. 조직 좌석은 조직 정책·관리자 설정을 따르고, 개인 프로젝트에 써도 되는지는 조직이 정합니다. 정리에 쓴 사용량은 그 좌석·구독 한도에서 빠지고(chat·Cowork 와 합산), 한도에 닿으면 정리가 멈춥니다. 조직 관리자는 사용자별 사용량을 볼 수 있습니다. 서버는 Claude 로그인 정보를 받지 않습니다.

1. **말하기 · 원문 던지기** — [대화]를 누르면 오른쪽(휴대폰은 화면 전체)에 서랍이 열립니다. 겪은 일을 말하거나 내가 쓴 원문을 통째로 붙여 넣고 [보내기]. 한 번에 8,000자까지입니다(칸 아래 숫자).
   - **원문으로 저장** — 붙여 넣은 원문도 그대로 「내 글」로 남기려면 첫 입력 때 체크합니다. 첫 입력에서만 고르고, 그 대화가 끝날 때까지 바뀌지 않습니다.
2. **정리 기다리기** — 서랍 아래 한 줄에 상태가 뜹니다. 「PC 가 받기를 기다리고 있어요」면 PC 가 아직 받지 않은 것입니다. 걸리는 시간은 정해져 있지 않습니다.
   - 서랍 머리글의 **최근 연결** 은 서버가 최근 PC 신호를 받았다는 뜻입니다. 정리가 된다는 보장은 아닙니다 — PC 의 CLI 로그인·구독 사용량은 서버가 모릅니다.
   - **PC 오프라인 · 마지막 연결 …** 이면 보낸 작업이 PC 연결을 기다립니다. 연결되지 않으면 작업이 취소되거나 대화가 만료될 수 있습니다.
3. **확인 1번** — 「이렇게 정리했어요. 맞나요?」 카드가 뜹니다.
   - **정리 글** — 문장 칸. 바로 고칠 수 있습니다. 고치면 [확정]이 곧바로 잠기고, 정리 글 밖을 누르면 고친 글로 다시 정리합니다(재정리). 새 결과가 뜨면 [확정]이 다시 켜집니다. 문장 옆 「추정」은 AI 가 문맥으로 대상을 고른 것입니다 — 맞지 않으면 고치거나 아래에서 끕니다.
   - **바뀌는 것** — 이 확인으로 저장될 변경 목록. 전부 켜져 있습니다. 틀린 것만 끕니다. 끄면 거기 기대는 변경과 그 문장도 함께 빠집니다. 빠진 변경은 「반영 안 함」 아래에 보이고, 확정해도 저장되지 않습니다.
   - **정해 주세요** — AI 가 정하지 못한 것(대상이 누구인지 등). 답을 적고 Enter 를 누르면 그 답으로 다시 정리합니다. 남아 있는 동안 [확정]은 잠겨 있습니다.
   - **[확정]** — 정리 글과 켜 둔 변경을 한 번에 저장합니다. 「저장했어요 · 변경 N」이 뜨고 「나」의 숫자·목록이 바뀝니다. 내가 누르기 전에는 아무것도 저장되지 않습니다.
   - **[삭제]** — Setup 에 「휴지통」이 보일 때만. 이 정리를 저장하지 않고 휴지통으로 옮깁니다. 168시간 안에 복원하면 확정 전 상태로 돌아갑니다(PC 작업은 다시 시작하지 않습니다).
4. **이어 받기** — 확정 전 결과는 첫 입력부터 24시간 서버에 임시 보관됩니다(더 말하거나 다시 정리해도 늘어나지 않습니다. 휴지통에 있는 동안은 남은 시간이 멈춥니다). 새로 고침하거나 다른 탭·기기에서 열어도 최신 결과가 다시 뜹니다. 두 곳에서 [확정]을 누르면 최신 결과를 본 쪽만 저장됩니다.

확정한 정리 글은 「내 글」(대화 정리)로 남고 판단의 근거로 인용할 수 있습니다. 대화 원문은 PC 에만 남습니다. 확정한 기준 문장을 대화로 바꾸면 덮어쓰지 않고 새 판을 만들며, 이전 판은 이력으로 남습니다. 서랍의 대화 표시는 그 화면에만 있어 새로 고침하면 사라집니다 — 최신 정리 결과는 남습니다.

## 3. 하고 싶은 일 → 이렇게 말하세요

대화에서 말하면 AI 가 알맞은 도구를 부릅니다. 예시 문장은 그대로 따라 하지 않아도 됩니다 — 뜻이 같으면 됩니다.

「결과가 보이는 곳」은 새 탐색 기준입니다(4절). 새로 가입한 계정은 처음부터 새 탐색입니다. 수락하기 전 화면은 4절 끝.

| 하고 싶은 일 | 이렇게 말하세요(예) | 어디서 | 결과가 보이는 곳 |
|---|---|---|---|
| 글 남기기(출처 포함) | "기록 남길게. 출처는 「주간 회의 메모」 파일이야. …(내 글 그대로)" | 대화 | 「나」 › 요약 「최근 변경」 · 출처 탭의 그 출처 · Setup › 자료 종류 › 내 글 — 글에 출처가 붙습니다. 출처를 말하지 않으면 「출처 미확인」 |
| 검토할 판단 뽑기 | "방금 기록에서 후보 뽑아 줘" | 대화 | 「나」 › 요약 「기다리는 결정」 › 검토할 판단 |
| 판단 확정 | "첫 번째는 남길게. 두 번째는 빼 줘. 세 번째는 이렇게 고쳐서 남길게: …" 또는 웹 상세 [남기기] · [고쳐서 남기기] · [반영 안 함] | 대화 또는 웹 | Setup › 자료 종류 › 검토할 판단 화면의 「확정한 판단」 · 근거 글 상세의 「연결」 |
| 질문 세우기 | "이 질문 남길게: 언제 표준으로 가고 언제 직접 만드나?" | 대화 | Setup › 자료 종류 › 질문 |
| 축에 글 붙이기 | 축 항목이 먼저 있어야 합니다. ① "축 항목 「범위 관리」 만들어 줘" → "적용해 줘" ② "방금 기록을 「범위 관리」 축에 붙여 줘" | 대화(① 적용은 웹 Setup › 자료 종류에서도) | 「나」 › 축 탭에서 그 축을 고르면 옆 「이 축에 묶인 데이터」에 붙은 글이 보이고, 축 띠 숫자가 늘어납니다 |
| 결정 남기기 | "이 두 판단을 근거로 결정 하나 제안해 줘: 「A사 견적은 표준으로 간다」" → "적용해 줘" | 대화로 제안, 적용은 대화 또는 웹 | 「나」 › 결정 탭 |
| 기준 세우기 | "확정한 판단 두 개로 기준 하나 제안해 줘: …" → 웹 Setup › 자료 종류 › 기준에서 제안 확인 → "적용해 줘" → "이 기준 확정할게" | 대화로 제안, 적용·확정은 대화 또는 웹 | 「나」 › 기준 탭 — 근거는 옆 「근거·연결」. 승격 조건 충족 여부는 Setup › 자료 종류 › 기준 카드를 열면 보입니다 |
| 내 자료 종류 만들기 | "프로젝트를 따로 쌓고 싶어. 결정과 이어지게 정의 제안해 줘" → AI 가 보여 주는 미리보기 확인 → "적용해 줘" | 대화 | 「나」 › 커스텀 탭 · Setup › 자료 종류 · Setup › 내 구조 설정 — 구분 「커스텀」 |
| 공통 구조 적용 검토 | 말하지 않습니다. 웹에서 고릅니다 | 웹 — Setup › 내 구조 설정 › 고급 › 공통 구조 적용 검토 › 편입·보류·거절 | 같은 화면의 상태 표시. **이미 쓰던 계정만** 고릅니다 — 새 계정은 처음부터 표준이 들어 있습니다 |
| 남의 글이었다고 표시하기 | "이 기록은 내가 쓴 게 아니라 남의 글이었어. 기록 정보 고쳐 줘" | 대화 | 그 글은 판단 근거로 쓸 수 없게 됩니다. 그 글에서 검토할 판단을 이미 뽑았다면 바꿀 수 없습니다 |
| 자료 종류 보관·되살리기 | "프로젝트 자료 종류 보관해 줘" — AI 가 먼저 그 자료 종류의 항목 수와 그것을 가리키는 다른 필드 수를 알려 줍니다. 되살릴 때 "보관한 프로젝트 자료 종류 다시 꺼내 줘" | 대화 | 보관하면 「내 구조 설정」 목록에서 빠지고, 되살리면 다시 보입니다. 항목은 지우지 않습니다. 보관한 목록은 대화에서 "보관한 자료 종류 보여 줘". 표준(축·결정·기준)과 아직 적용하지 않은 제안은 보관할 수 없습니다 |
| 적용 전 제안 다시 보기 | 제안한 그 대화에서 "아까 제안한 프로젝트 정의 다시 보여 줘" — AI 가 그 제안을 콕 집어 다시 읽습니다 | 대화 | 대화에서만. 적용 전 새 자료 종류 제안은 화면 목록에 나오지 않습니다 |
| 표시 이름 정하기 | "내 표시 이름을 「새벽」으로 바꿔 줘" 또는 웹 이름 입력 화면 · 「나」 맨 위 이름 누르기 · 계정 메뉴 「표시 이름 바꾸기」 | 대화 또는 웹 | 「나」 맨 위 |
| 사람 남기기 | "사람 이름표 하나 만들어 줘: 「옆팀 리드」" — 이름표 하나만(별칭 권장) | 대화 또는 웹(Setup › 자료 종류 › 사람) | 「나」 › 사람 탭 |
| 읽고 든 생각 남기기 | "「주간 회의 메모」 출처에 내 반응 남길게: …" · 확인한 뒤 "이 반응 확인했다고 표시해 줘" | 대화 또는 웹(「나」 › 출처 탭의 「읽고 든 생각 쓰기」 · Setup › 자료 종류 › 읽고 든 생각) | 「나」 › 출처 탭의 그 출처 — 처음엔 「확인 전」 |
| 내 PC 연결하기(연결 장치) | 말하지 않습니다. 웹에서 합니다 | 웹 — Setup › 연결 장치(계정 메뉴 「연결 장치」도 같은 곳) › 장치 이름 적고 연결 → 한 번만 보이는 토큰을 PC 의 로컬 에이전트 연결 단계에 붙여 넣기 | 연결 장치 화면 — 상태·만료 예정·허용 규칙. 토큰은 대화·문서·메신저에 붙여 넣지 않습니다 |

| 활동 현황 보기 | "최근 30일 내 활동 집계 보여 줘"(7일·90일·전체도) | 대화 또는 웹 | Setup › 자료 종류 › 활동 › 「활동 현황」(접혀 있음) — 행동별·축별·자주 반응한 사람·출처 구성·날짜 미확인. 계산 규칙은 숫자 옆 「?」. 성향 평가가 아닙니다 |

| 원문 보기 | 말하지 않습니다 | 원문을 보관한 PC 의 브라우저 — 활동 상세 [원문 열기 · 이 PC] → 로컬 화면의 [원문 열기] | 그 PC 의 로컬 에이전트 화면. 서버는 원문을 가져오지 않습니다 |
| 계정 삭제 요청 | 웹 Setup › 문의 및 개인정보 › [개인정보 요청](계정 메뉴에도 있음)에 "계정을 삭제해 주세요" 한 줄. 대화에서 "계정 삭제 요청 보내 줘"라고 해도 됩니다(보낼 글을 먼저 확인) | 웹 또는 대화 | Setup › 문의 및 개인정보 › [내 문의] — 절차는 [11. 처리방침](11-privacy.md) 3절 |

AI 는 제안만 합니다. 적용·확정·남기기·확인했어요는 내가 말하거나 버튼을 눌러야 됩니다. 저장 승인 대기 글의 승인·거절과 웹 「대화」의 [확정]은 웹 버튼으로만 됩니다.

## 4. 화면

탭은 셋 — **나 · 오늘 · Setup**.

**「나」(첫 화면)**
- 맨 위에 표시 이름(눌러서 고칩니다). 그 아래 하위 탭 일곱 — **요약 · 기준 · 결정 · 축 · 커스텀 · 사람 · 출처**. 순서는 Setup › 페이지 레이아웃에서 바꿉니다.
- 하위 탭 이름 옆 🔒 은 **기본**(모든 사용자에게 같은 종류)입니다. 🔒 이 없는 「커스텀」은 내가 들인 종류입니다. 숫자는 그 종류 전체 건수입니다.
- **축 띠** — 하위 탭 아래. 축마다 직접 연결된 항목·글·읽기 자료 수의 비율을 색 띠로, 그 아래 칩에 축 코드·이름·건수를 보여 줍니다. 축 색은 코드 순으로 정해지고 아홉 번째부터는 회색입니다 — 건수가 바뀌어도 색은 그대로입니다. 칩을 누르면 축 탭에서 그 축이 열립니다.
- **요약** — 13주 글·활동 · 종류별 건수 · 기다리는 결정(검토할 판단 · 확정 전 기준 · 저장 승인 대기) · 최근 변경 5. 13주 칸은 날짜가 확인된 글·활동만 셉니다 — 날짜를 모르는 글은 빠집니다. 버튼은 없고, 이름을 누르면 그 화면으로 갑니다.
- **렌즈** — 기준·결정은 「근거 역추적」, 축은 「축 묶음」, 사람은 「사람 관계」로 봅니다. 왼쪽 목록 · 가운데 고른 데이터(내용 · 할 수 있는 동작 · 연결 그래프) · 오른쪽 종류별 연결 목록(종류마다 다섯 줄, 더 있으면 [더 N]). 탭을 처음 열면 연결이 가장 많은 행이 열립니다. 고른 데이터는 주소에 남아 뒤로 가기·새로 고침에도 그대로입니다.
- **커스텀 · 출처** — 목록과 상세. 출처 상세에는 그 출처의 내 글 · 읽고 든 생각 · 활동이 나오고, 불러온 글보다 많으면 [더 보기].
- 내 글 · 질문 · 판단 · 읽고 든 생각은 하위 탭이 아닙니다 — 연결·근거 링크를 누르면 그 상세가 열립니다.
- 데이터가 하나도 없으면 「아직 표시할 데이터가 없어요. 데이터가 들어오면 여기서 볼 수 있어요.」

**휴대폰** — 화면이 좁으면(768px 미만) 한 열로, 목록 → 상세로 넘어갑니다. 상세 위 [목록]이나 브라우저 뒤로 가기로 돌아옵니다.

**연결** — 고른 데이터와 실제로 저장된 관계로 이어진 데이터만 그립니다. 그래프의 점을 누르면 그 데이터로 옮겨 갑니다. 많으면 그래프는 일부만 그리고 「노드 N개·연결 M개 생략」을 띄웁니다 — 옆 목록에서 전부 볼 수 있고, 「전체 종류」 선택으로 종류를 거를 수 있습니다. 커스텀과 내 글·질문·판단 상세에서는 [목록으로 보기] · [그래프로 보기]로 바꿔 봅니다.

**클릭 편집** — 상세에서 「눌러서 고치기」가 뜨는 값을 누르면 입력 칸과 [저장] · [취소]가 나옵니다. [고쳐서 남기기]도 같습니다 — 「고친 문장」 칸에 적고 [저장]. [저장]을 눌러야 반영됩니다 — 고르기·입력·다른 곳 누르기로는 저장되지 않습니다. 저장하지 않고 다른 데이터로 옮기면 「저장하지 않은 변경이 있어요」 창에서 [계속 편집] · [변경 버리기]를 고릅니다. 고칠 수 있는 것은 5절.

**[수정]** — 내 글·기준·결정·축·커스텀 상세에 [수정]이 있습니다. 제목·본문 칸과 「저장하면 이 글이 확정됩니다」가 나오고, [저장]을 누르면 그대로 확정입니다. 바뀐 게 없으면 [저장]이 눌리지 않습니다. Setup 에 「휴지통」이 보이면 확정 전 기준의 상세 버튼은 [남기기] · [수정] · [삭제], 확정한 기준과 다른 항목·내 글은 [수정] · [삭제]입니다. AI 의 적용 전 제안이 걸린 항목은 [수정]이 없습니다 — 제안을 적용하거나 지운 뒤 고칩니다. 판단의 근거를 열면 그 판단이 가리키는 판이 열리고, 고치기 전 판이면 「예전 판」과 [최신 글 보기]가 붙습니다. 말 뜻은 [10. 말 뜻](10-words.md) 「글 수정」.

**「오늘」** — 들어온 것 전부를 들어온 날(한국 시간) 머리글로 묶습니다.
- 「대기」 = 저장 승인 대기 글. 누르면 옆(휴대폰은 아래)에 본문과 [승인] · [제외](Setup 에 「휴지통」이 보이면 [삭제])가 나옵니다.
- 「보관됨」 = 승인해 저장된 내 글과 연결 장치가 보낸 활동. 날마다 활동은 다섯 줄, 더 있으면 [더 N].
- 탭 이름 옆 숫자는 승인 대기 수입니다. 지난 승인 대기(승인함 · 반영 안 함 · 만료)는 목록 아래 링크로 봅니다. 「오늘」 목록에는 삭제가 없습니다.

**Setup**

| 페이지 | 들어 있는 것 |
|---|---|
| 페이지 레이아웃 | 「나」 하위 탭 순서와 요약 블록 순서. 끌어 놓으면 바로 저장됩니다(키보드는 항목에서 Alt + 화살표, 휴대폰은 ⠿ 손잡이). [기본으로 되돌리기]. 다른 창에서 먼저 바꿨으면 「다른 화면에서 먼저 바뀌어 최신 배치를 불러왔어요」 — 다시 옮기면 됩니다 |
| 내 구조 설정 | 자료 종류·필드·관계 [그래프](기본) · [목록] · 「구조 이름 공유」(켜짐/꺼짐) · 「고급」 › 「공통 구조 적용 검토」 |
| 자료 종류 | 모든 자료 종류 — 「기본 🔒」 · 「내 탭」 · 「커스텀」 묶음. 질문 · 내 글 · 검토할 판단 · 출처 · 사람 · 읽고 든 생각 · 활동 · 문의와, 기준·결정·축처럼 종류마다 항목을 모아 보는 화면. 「내 탭」은 설정 때 이름 지은 글·질문 탭입니다. 「검토할 판단」 카드는 아직 안 정한 판단만 엽니다 |
| 연결 장치 | PC 연결 · 토큰 재발급 · 연결 해제 · 허용 규칙 |
| 지도 | 지도는 홈과 겹치는 데이터를 '들어오는 것·내 손 대기·쌓이는 재료'로 나눠 보여줍니다 |
| 문의 및 개인정보 | [문의 보내기] · [내 문의] · [개인정보 요청] |
| 휴지통 | 보일 때만(서버가 휴지통을 켰을 때). 삭제한 것 — 종류·제목·삭제 시각·복원 가능 기한 · [복원] · [영구 삭제] |

**휴지통** — Setup 에 「휴지통」이 보이면 지우는 버튼이 [삭제] 하나입니다. 저장 승인 대기 글·제안·확정 전 대화 정리를 거절할 때도 [삭제]입니다. 삭제한 것은 삭제 시각부터 168시간 동안 Setup › 휴지통에서 [복원]할 수 있고, 기한이 지나거나 [영구 삭제]를 누르면 복원할 수 없습니다. 본문은 이후 서버 정리 때 지웁니다. 복원은 승인·적용·확정이 아니고 원래 상태로 돌아갈 뿐입니다. 말 뜻은 [10. 말 뜻](10-words.md) 「휴지통」.

**대화** — 탭 줄 오른쪽(켜진 계정만). 서랍의 버튼은 셋 — [보내기] · [확정] · [닫기](Setup 에 「휴지통」이 보이면 확인 카드에 [삭제]도). 닫아도 확정 전 결과는 보관시간(첫 입력부터 24시간) 동안 남습니다. 쓰는 법은 2-1절.

**계정 메뉴** — 표시 이름 바꾸기 · 내 구조 설정 · 저장 승인 대기 (N)(0 이면 숫자 없음) · 연결 장치 · 문의 및 개인정보(문의 보내기 · 내 문의 · 개인정보 요청) · 로그아웃(6절). 내 구조 설정 · 연결 장치는 Setup 의 같은 페이지를, 저장 승인 대기는 「오늘」을 엽니다.

**옛 링크** — 저장해 둔 링크는 새 자리로 옮겨 열립니다: `#_obj` → Setup › 자료 종류 · `#_settings` → Setup › 내 구조 설정 · `#_devices` → Setup › 연결 장치 · `#map` → Setup › 지도 · `#_inbox` · `#today` → 「오늘」 · 항목 하나 링크 → 「나」의 그 탭. 자료 종류의 상세(사람·출처·활동 하나) · 종류별 항목 화면(`#structure/…`) · 판단 대조 링크는 그대로 열립니다.

**새 탐색을 수락하기 전 화면** — 이미 쓰던 계정은 계정 메뉴 「새 탐색으로 바꾸기」에서 한 번 수락할 때까지 아래 다섯 탭을 씁니다. 데이터는 같고, 표준 편입과 따로이고, 되돌리는 화면은 없습니다.

| 탭 | 보이는 것 |
|---|---|
| 오늘 | 아직 안 정한 판단(질문별·글별), [원문과 대조하기], 다음 할 일 / 오른쪽에 최근 글과 원문 읽기 판 |
| 질문 | 질문 하나씩 한 장 — 확정한 판단 · 아직 안 정한 판단 · 반영 안 한 판단 · 연결된 글 |
| 기록 | 글 원문 전체와 그 글에서 나온 판단. 글마다 출처(파일·웹 주소·대화)가 붙고, 없으면 「출처 미확인」. 위쪽 필터로 출처별로 봅니다 |
| 구조 | 두 보기 — **항목**: 기준·결정·축 등이 카드로, 누르면 오른쪽 서랍에 본문·근거·이력·제안 · **구조 정의**: 내 자료 종류·필드·관계를 목록과 그림으로, 「표준 편입 미리보기」(= 공통 구조 적용 검토) |
| 지도 | 흐름 세 열 — 들어오는 것(판단을 뽑지 않은 글) · 내 손 대기(아직 안 정한 판단) · 쌓이는 재료(확정한 판단·기준) |

맨 위 막대는 오늘의 상태(확정한 판단·아직 안 정함·반영 안 함·판단을 뽑지 않은 글 비율)이고, 그 아래 질문마다 미결정 수와 [한 장]이 있습니다.

## 5. 웹에서 할 수 있는 것과 없는 것

- **할 수 있는 것**: 보기 · 「나」 하위 탭 순서·요약 블록 순서 바꾸기(Setup › 페이지 레이아웃) · 검토할 판단 결정(남기기 · 고쳐서 남기기 · 반영 안 함 · 되돌리기) · 기준·항목 결정 · AI 가 낸 제안의 [제안 적용] · [제안 제외](Setup 에 「휴지통」이 보이면 [삭제]) · 공통 구조 적용 검토(편입·보류·거절) · 표시 이름 정하기·바꾸기 · 새 탐색 수락 · 사람 추가·별칭 고치기·지우기 · 출처 추가 · 읽고 든 생각 추가·고치기·지우기와 [확인했어요] · [확인 전으로] · 연결 장치 연결·토큰 재발급·연결 해제·허용 규칙 바꾸기 · 저장 승인 대기 승인·거절 · 활동 보기 · 내 글·항목 제목·본문 [수정](저장 = 확정) · Setup 에 「휴지통」이 보이면 [삭제] · [복원] · [영구 삭제] · 「문의 보내기」·「개인정보 요청」·「내 문의」 · 「대화」가 켜져 있으면 말하기·원문 던지기·정리 글 고치기·변경 끄기·[확정](2-1절).
- **없는 것**: 질문·검토할 판단·기준 **추가**, 자료 종류 보관·되살리기, 적용 전 정의 제안 보기 — 전부 연결한 AI 대화에서 합니다. 내 글 추가도 연결한 AI 대화에서 합니다(「대화」가 켜져 있으면 웹 대화의 [확정]으로도 남습니다). 출처·질문 고치기(내 글은 [수정]으로 고칩니다), 확정한 판단 문장 고치기(남긴 뒤엔 덮어쓰지 않음), 데이터 사이 연결 추가도 없습니다. 활동 추가·고치기·지우기도 없습니다 — 활동은 연결 장치만 보냅니다. 처음 받은 원문은 어디서도 지워지지 않습니다 — 내 글을 고쳐도 첫 판으로 남습니다.

## 6. 로그아웃

[로그아웃] → 시작 화면 "로그아웃했어요". 거기서 [로그인]을 누르면 계정을 다시 고를 수 있습니다. 그냥 주소로 들어가면 로그인 서버가 기억한 계정으로 바로 들어가요.

## 7. 막힐 때

따옴표 안은 화면·대화에 실제로 뜨는 문구라 예전 말(기록·후보 등)이 남아 있을 수 있습니다.

| 현상 | 뜻 |
|---|---|
| "대시보드에서 표시 이름을 정해 주세요" | 표시 이름을 아직 정하지 않았습니다. 웹에 로그인해 이름을 정하거나, 대화에서 "내 표시 이름을 …로 해 줘" |
| "이 판단의 근거 구절이 저장된 원문과 일치하지 않아 남길 수 없어요" | AI 가 인용을 틀리게 보냈습니다. 대화에서 "후보 다시 뽑아 줘" |
| "다른 곳에서 먼저 바뀌었어요…" | 대화와 웹에서 같은 것을 동시에 바꿨습니다. 화면이 최신 내용을 다시 불러왔으면 확인하고 다시 하고, 아니면 새로 고침. [수정] 중이면 최신 글을 위에 보여 주고 쓰던 내용은 그대로 둡니다 — 비교한 뒤 다시 [저장] |
| "이 글은 삭제됐거나 휴지통에 있어 저장할 수 없어요…" | [수정] 중에 그 글이 삭제됐습니다. 쓰던 내용은 편집 칸에 남아 있으니 필요하면 복사해 두세요. 휴지통에서 [복원]한 뒤 다시 [수정] |
| "이 데이터를 열 수 없어요." | 링크한 데이터가 지워졌거나 열 수 없습니다. [목록으로] |
| "통계를 불러오지 못했어요. 새로 고침해 주세요." | 「나」의 축 띠·요약 숫자를 서버에서 받지 못했습니다. 다른 화면은 그대로 씁니다. 새로 고침 |
| "저장하지 못해 전 배치로 돌렸어요. 다시 옮겨 주세요." | 페이지 레이아웃 저장이 실패해 마지막으로 저장된 순서로 돌아갔습니다. 다시 끌어 놓으세요 |
| 「확정 전 재검토」 · "근거 글의 작성자를 확인할 수 없어…" · "근거 글이 원문 그대로가 아니라…" | 그 판단의 근거 글이 인용 조건(내가 직접 쓴 원문 그대로)을 못 채웁니다. 조건은 그 판단이 가리키는 판으로 따지므로, 글을 [수정]해도 이미 뽑힌 판단은 그대로입니다. 반영 안 함·아직 안 정함은 됩니다. 작성자·가공 방식 표시가 **실제로 틀렸을 때만** 연결한 AI 대화에서 "이 기록은 내가 직접 쓴 원문 그대로야. 기록 정보 고쳐 줘"라고 말하세요 — AI 가 글 정보를 고칩니다. 화면 안내에 영어 도구 이름이 보여도 내가 직접 부를 필요는 없습니다 |
| 「확정 전 재검토」 · "근거 글이 남이 쓴 글이라…" · "근거 글이 삭제돼…" | 그 판단은 확정할 수 없습니다. 반영 안 함·아직 안 정함만 됩니다 |
| "이 기록을 근거로 한 후보가 …개 있어 본인 원문이 아니라고 바꿀 수 없어요" | 이미 검토할 판단을 뽑은 글은 「남의 글」 등으로 바꿀 수 없습니다. 그 판단은 반영 안 함으로 두고, 꼭 고쳐야 하면 「문의 보내기」 |
| "표준 필드는 뺄 수 없어요" · "표준 필드의 key·value_type·대상·multiple·required 는 바꿀 수 없어요" · "표준 오브젝트의 key 는 바꿀 수 없어요" · "표준 오브젝트는 삭제·보관할 수 없어요" | 편입한 표준 정의(「표준 정의 보호」)의 표준 부분을 바꾸거나 보관하려 했습니다. 표준 정의는 label(표시명)만 바꿀 수 있어요. 필드·선택지는 더할 수 있어요 |
| "적용 전 제안은 보관할 수 없어요" | 아직 적용하지 않은 정의 제안이라 보관할 것이 없습니다. 그대로 두거나 새 제안으로 덮으세요 |
| "이 사람은 연결돼 있어 지울 수 없어요(…)" | 그 사람이 활동·내 글·항목에 연결돼 있습니다. 서버는 연결을 몰래 끊지 않습니다. 별칭은 바꿀 수 있어요 |
| "AI 요약으로 보관한 기록은 출처 판정을 바꿀 수 없어요" | 저장 승인 대기에서 승인한 내 글 AI 요약은 내가 직접 쓴 원문으로 바꿀 수 없습니다. 직접 쓴 글은 새로 남기세요 |
| "지금은 서버가 장치에서 보내는 자료를 받지 않아요(준비 중)" | 서버가 아직 장치 자료를 받지 않습니다. 연결은 미리 해 둘 수 있고, 보낼 자료는 PC 에 남아 있습니다 |
| "연결된 장치가 5대라 더 연결할 수 없어요" | 쓰지 않는 장치를 연결 해제한 뒤 연결하세요 |
| 「토큰 만료 · 재발급 필요」 | 장치 토큰이 90일이 지나 만료됐습니다. 연결 장치 화면에서 [토큰 재발급] → PC 의 로컬 에이전트에 새 토큰을 넣어 다시 연결 |
| "승인 대기 글의 승인이 지금 꺼져 있어요" | 서버가 아직 승인을 받지 않습니다. 대기 글은 그대로 남고, 거절([제외] 또는 [삭제])은 됩니다 |
| "더 새 개정이 들어와서 이 개정은 승인할 수 없어요" | PC 에서 같은 글이 다시 바뀌어 들어왔습니다. 최신 개정을 열어 승인하세요 |
| "지금은 승인할 수 없어요(만료됐거나 이미 처리됐어요)" · "이미 처리한 승인 대기예요" · "보관 기간이 지난 승인 대기예요" | 대기시간 30일이 지나 만료됐거나 이미 승인·거절했습니다. 목록을 새로 고치세요 |
| 「PC 가 받기를 기다리고 있어요… PC 가 켜져 있어야 정리돼요.」 | 웹 「대화」의 정리는 연결 장치가 합니다. 그 PC 가 켜져 있고 로컬 에이전트가 도는지 확인하세요 |
| 「PC 쪽 정리가 끝났는지 알 수 없어요…」 | PC 의 정리가 끝났는지 서버가 확인하지 못해 같은 대화를 다시 돌리지 않았습니다. 연결 장치를 확인한 뒤 다시 보내세요 |
| 「이 결과는 최신이 아니에요…」 | 다른 탭·기기에서 같은 대화를 더 새로 정리했거나 이미 확정했습니다. 화면이 최신 결과를 다시 불러오면 확인하고 다시 [확정] |
| 「정리한 뒤 대상이나 구조가 바뀌었어요. 다시 정리할게요.」 | 정리한 뒤 대상 항목이나 내 구조가 바뀌어 그대로 저장하지 않았습니다. 다시 정리된 결과를 확인하고 [확정] |
| 「대화가 만료됐어요(첫 입력 뒤 24시간)…」 | 확정 전 결과는 보관시간(첫 입력부터 24시간, 휴지통에 있던 시간은 빼고)이 지나 지워졌습니다. 새로 보내세요 |
| 「오늘 남길 수 있는 글 수를 넘었어요…」 | 하루 글 한도를 넘어 아무것도 저장하지 않았습니다(원문으로 저장은 원문·정리 2편으로 셉니다). 한도가 풀린 뒤 24시간 안이면 다시 [확정] |
| [원문 열기 · 이 PC] 가 안 열림 | 원문을 보관한 그 PC 에서만 열립니다. 그 PC 에서 로컬 에이전트의 원문 보기를 켰는지, 버튼 아래 「로컬 연결 포트」가 같은지(기본 8790) 확인하세요 |
| 첫 응답이 느림 | 무료 서버가 깨는 중(30~60초) |
| 로그인했는데 빈 화면 | 아직 데이터가 없습니다. 대화에서 글 1편부터 |

용어는 [10. 말 뜻](10-words.md).
