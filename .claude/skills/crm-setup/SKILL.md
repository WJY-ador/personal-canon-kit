# crm-setup — 설정 대화

사용자의 목적·질문·첫 자료·탭을 **사용자의 말로** 정한다. 너는 구조화하고 제안할 뿐, 확정은 사용자가 한다.

## 계약

| 항목 | 내용 |
|---|---|
| 전제 | 제품 폴더에서 실행. `python3 crm.py where` 에 데이터 폴더가 보여야 함 (없으면 `init` 부터 안내) |
| 입력 | 사용 목적, 사용자가 고른 자기 글/메모, 흩어진 자료 위치, 매일 볼 것 최대 3개 |
| 읽기 | **동의한 경로만.** 동의 전에는 어떤 파일도 열지 않는다. 전체 디스크·홈 폴더 탐색 금지 |
| 쓰기 | `crm.py` 명령으로만. 데이터 폴더의 JSON 을 직접 편집하지 않는다 |
| 모델 전송 | 이 대화 자체가 사용자의 Claude Code 세션이다. 사용자가 고른 글을 읽는 것도 전송임을 처음에 말한다 |
| 출력 | 확인/추정/미입력/꺼 둠 상태의 프로필, 질문 0~1개, 자료 0~1종, 승인된 탭, 보류 요구, 마지막 완료 단계 |
| 완료 | 마무리 보고 4줄: 확인된 것 / 남은 것 / 꺼 둔 것 / 다음 행동 1개 |

## 순서

0. `python3 crm.py status` 로 진행 상태를 읽는다. 완료된 단계는 건너뛰고, 답이 있는 항목은 다시 묻지 않는다.
1. **동의 먼저.** 묻는다: "어느 폴더(또는 파일)를 읽어도 될까요? 정리할 때 기록 1편을 모델로 보내도 될까요?"
   답을 그대로 `python3 crm.py consent --read "<경로>" --model-send yes|no` 로 남긴다.
   민감·회사·타인 자료가 섞였다고 하면 그 파일을 범위에서 빼는 법을 먼저 안내한다.
2. **읽고 추정.** 동의 경로 안에서 사용자가 지목한 글만 읽는다. 알 수 있는 것을 3줄 이내로 "추정"이라 밝혀 보여 준다.
   맞다는 것만 `profile set <항목> "<사용자 표현>" --status confirmed --source "사용자 답"`.
   확인 전 추정은 `--status guessed --source "글 추정"` 으로만 남긴다.
3. **모르는 것만 한 묶음.** 미입력 항목 중 최대 3개를 한 번에 묻는다. 사용자 표현을 바꾸지 말고 그대로 저장한다.
   건너뛰겠다면 `--status off`.
4. **질문.** "계속 돌아오는 질문이 있나요?" — 있으면 사용자 문장 그대로 `question add`.
   **없으면 만들지 않는다.** `setup done question` 하고 "최근 경험 메모 1편부터"로 간다. 축을 대신 지어 주지 않는다.
5. **첫 자료 1종.** `source add "<경로>" --label "<사용자 이름>"`. 모르면 넘어간다.
6. **탭.** 매일 볼 것(최대 3개)을 사용자 말로 탭 이름에 쓴다. `python3 crm.py blocks` 의 카탈로그에서만 블록을 고른다.
   카탈로그에 없는 요구는 만들지 말고 `request "<사용자 표현>"` 으로 남긴다.
   `tabs propose --tab "<이름>=<블록,…>"` 의 미리보기 출력을 **그대로** 보여 주고 승인을 묻는다.
   승인 → `tabs apply`. 수정 → 다시 propose. 취소 → `tabs cancel`.
7. **마무리 보고** 4줄. 다음 행동은 `python3 crm.py next` 의 결과를 쓴다.

## 중단·실패

- 사용자가 멈추면 그 자리에서 끝낸다. 진행 상태는 이미 각 명령이 남겼다. 다음에 0번부터 다시 하면 이어진다.
- `crm.py` 가 `[오류 …]` 를 내면 그 "다음 조치" 줄을 사용자에게 그대로 보여 주고, 임의로 우회하지 않는다.
- 같은 오류가 두 번이면 멈추고 `crm-doctor` 스킬로 넘긴다.

## 하지 않는 것

- 동의 범위 밖 파일 읽기, 범위 임의 확대
- 추정을 확인 없이 confirmed 로 저장
- 타인 발화를 사용자 프로필·판단으로 저장
- 질문·판단을 대신 지어 확정
- 카탈로그 밖 블록 생성, 제품 코드 수정
